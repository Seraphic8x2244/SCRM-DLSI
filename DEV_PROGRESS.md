## Product / architecture contract
- Companion plugin to SCRM (Vanilla WoW 1.12.1 / Lua 5.0.3). DLSI owns advanced immunity observations, transient safety, learning, persistent HearthDB knowledge, diagnostics, alerts and UI; SCRM stays an independent macro host.
- Exactly **one** DLSI Lua file; preserved original internal module sections and listener/inference logic: Observations, Storage, Transient, Knowledge, UI. The original source was consolidated into five private loader functions; learner algorithms, success/ambiguous IMMUNE paths, target safeguards, uncertainty, DR/TempCC/reflection/death exclusions and hypothesis persistence must remain unchanged. Do not transplant unrelated fork Utility/Core code.
- Distinct Lua 5.0 `setfenv` loader environments and DLSI facade; no `_G.CleveRoids` module rebinding or host-global method overrides. Read-only private spell/effect/dispel, GUID/live creature-ID, aura/DR helpers adapt to the *frozen generic host*, not to fork-only prototype extensions.
- **One** normalized event source: the pre-existing private Observations frame; no duplicate normalized listener/router. It calls the original learner path only if initialization succeeded **and** the live selected provider is `scrm-dlsi`. Switching to Built-in stops DLSI learning immediately; host built-in automatic learning is dormant for the entire duration an external provider is selected, including missing/error/unknown. Host owns account-wide selection, no DLSI shadow selection or fallback.
- Provider registers through `CleveRoids.RegisterImmunityProvider("scrm-dlsi", "SCRM Deep Learning Immunities", check)` **only after** storage init and original module loading. The callback returns `true` for confirmed immunity/live applicable guard, `false` only for sufficiently evidenced vulnerability on complete applicable dimensions, `nil` for missing evidence, insufficient identity, unsupported/incomplete spell profile, unresolved classification, storage failure or other uncertainty. A broad `all`, `spell` or `cc` immunity can override positively; absence of broad negative facts does not block a proved exact vulnerability. No host legacy automatic learner data supplies DLSI answers. For player targets only proven live aura can return true; never consult NPC-template facts.
- Bare and named `[immune]`/`[noimmune]` use frozen host's existing macro front door and return semantics. In particular, a selected external provider yielding `nil` makes both conditional forms fail conservatively, without silent built-in fallback. DLSI's spell-name path resolves rank-stripped spell IDs and preserves canonical school/CC/dispel composition; do not conflate lack of an immune fact with proven vulnerability.
- **Data safety:** original file name `SuperCleveRoidMacros_Immunity.db`, schema version 1, and existing facts/hypotheses persist untouched. Storage opens before Knowledge and UI activation; mismatched version, nonempty unversioned schema, failed validation and missing HearthDB fail closed. No startup `ResetSchema`, delete, silent migration or merge. Handle closes on logout. Legacy `CleveRoids_ImmunityData` and `CleveRoidMacros.immunityBackups` stay host-owned and preserved, with DLSI UI backup/clear/restore/delete mutators disabled; legacy inspection is read-only. DLSI target diagnostics read their *own* Knowledge facts, not host legacy conclusions.
- All named UI/event/model frames use DLSI names; original layout is retained. Private `/dlsi` command opens original DLSI UI without overwriting host commands.
